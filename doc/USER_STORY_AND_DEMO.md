# User story and showcase demo

## User

The simulated patient is an awake adult in an ICU with an oral breathing tube. They temporarily cannot speak and have difficulty pointing or typing. They can understand a short question and give a deliberate yes or no. They want to describe a specific need and check the wording before sharing it. The caregiver wants to receive the patient's message and acknowledge it.

Use two volunteers to simulate the interaction. Place the CoreS3 so the patient volunteer can see the screen and the camera has the same framing used in testing. Hand the StickS3 to the caregiver volunteer.

## 60–90 second showcase

| Beat | What the audience sees |
| --- | --- |
| **Start** | The silent volunteer touches **Start** or uses a tested deliberate activation gesture. Explain that the check-in starts because the volunteer chose to start it. |
| **Report** | The device asks, **“Are you experiencing pain?”** The volunteer nods if camera input is verified, or selects **Yes** on the CoreS3. Show the accepted response. |
| **Clarify** | The device asks, **“Would you like help changing your position?”** The volunteer answers yes. |
| **Review** | The CoreS3 shows **“I'm in pain and would like help changing my position.”** The voice reads it back. The volunteer gives a separate **Send** or a fresh yes response. |
| **Deliver** | The StickS3 displays **“I'm in pain and would like help changing my position.”** |
| **Acknowledge** | The caregiver presses the StickS3 button. The CoreS3 shows **Caregiver acknowledged**. |

If the camera fails the reliability test, use the same dialogue with the touchscreen and say so before the run. If GPT-Live is unavailable, use local audio and identify it as the voice fallback. Use a live StickS3 connection for the two-device claim.

### Short second beat if there is time

Ask the question again and have the volunteer remain still. Show **No answer yet** or **Try again or use touch**. The session waits for the person's answer, and the caregiver receives no new message. This distinguishes a deliberate no from an unclear or missing response.

## Comparison for rehearsal

Use the same intended request and the same input method. A basic fixed-choice board can offer **Pain / Position / Temperature / Other**, then its fixed follow-up choices. Record the time and actions needed to reach the same intended message with the board and with the guided check-in. If the board is quicker, report that. ## One-sentence pitch

> We’re testing whether a person who can’t speak or easily use a tablet can answer a short check-in with an intentional movement, review their own message, and get a visible acknowledgment from a caregiver.
